# CarForm — مدیریت و چاپ اسناد فروش خودرو

یک برنامه دسکتاپ **آفلاین** برای ویندوز ۱۰/۱۱ (۶۴ بیتی) که با **C# + WPF روی .NET 8** و پایگاه داده **SQLite** ساخته شده است.
برنامه «فرم فروش خودرو / فاکتور رسمی» را می‌سازد، ذخیره می‌کند، چاپ می‌کند و به PDF خروجی می‌دهد؛ تمام تاریخ‌ها در رابط کاربر **شمسی (جلالی)** هستند.

---

## ۱. نیازمندی‌ها

| مورد | نسخه |
|---|---|
| سیستم‌عامل | Windows 10 / 11 (x64) |
| فریم‌ورک | .NET 8 SDK (`net8.0-windows`) |
| IDE | Visual Studio 2022 (17.8 یا بالاتر) با workload «.NET desktop development» |
| پایگاه داده | SQLite (فایل محلی، همراه برنامه ساخته می‌شود) |

نیازی به اینترنت در زمان اجرا نیست (فقط برای restore بسته‌های NuGet هنگام اولین build).

### بسته‌های NuGet استفاده‌شده

```
Microsoft.EntityFrameworkCore.Sqlite   8.0.11
Microsoft.EntityFrameworkCore.Design   8.0.11   (برای Migrationها؛ اختیاری)
Microsoft.Extensions.DependencyInjection 8.0.1
```

MVVM با کلاس‌های سبک داخلی (`ObservableObject`، `RelayCommand`، `AsyncRelayCommand`، `ViewModelBase`) پیاده‌سازی شده است تا هیچ وابستگی اضافه‌ای لازم نباشد.

## ۲. اجرا و Build

### با Visual Studio
1. فایل `CarForm.sln` را باز کنید.
2. پلتفرم را روی **x64** بگذارید (پیش‌فرض همین است).
3. `Build > Build Solution` و سپس **F5**.

### با خط فرمان
```bash
dotnet restore CarForm.sln
dotnet build CarForm.sln -c Release
dotnet run --project CarForm/CarForm.csproj
```

### انتشار (Publish)
```bash
dotnet publish CarForm/CarForm.csproj -c Release -r win-x64 --self-contained false -o .\publish
```
سپس `publish\CarForm.exe` را اجرا کنید.

> اولین اجرا به طور خودکار پوشهٔ بيانات، فایل `carform.db` و جدول‌ها را می‌سازد و حدود ۱۹ برند و بیش از ۱۰۰ مدل خودرو را به صورت پیش‌فرض درج می‌کند.

محل ذخیرهٔ داده‌ها:
```
%LOCALAPPDATA%\CarForm\
    Data\carform.db        پایگاه داده
    Images\                لوگو، تصویر مالکان و قالب چاپ
    Backups\               نسخه‌های پشتیبان
    Exports\               خروجی‌های PDF/CSV
```

## ۴. ماژول‌ها

1. **سند جدید (Wizard)** — ۶ مرحله: سربرگ، انتخاب خودرو، انتخاب مالک، رسیدها و بیمه، فاکتور، توضیحات.
2. **اسناد ذخیره شده** — جستجو بر اساس شماره، خریدار، خودرو، VIN و بازهٔ تاریخ شمسی؛ ویرایش، حذف، چاپ، PDF.
3. **خودروها** — مرور سه‌مرحله‌ای برند → مدل → خودروهای ثبت‌شده + CRUD برند/مدل/خودرو.
4. **مالکان** — شخص حقیقی / حقوقی، تصویر یا لوگو، کارت پروفایل حرفه‌ای، CRUD.
5. **تنظیمات شرکت** — نام، تلفن، کد پستی، نشانی، کد اقتصادی، شماره دستورالعمل کاردکس و شماره‌گذاری، لوگو.
6. **تنظیمات سند** — قلم، اندازه، رنگ‌ها، ترتیب بخش‌ها، تصویر قالب، ایمنی چاپ.
7. **گزارش‌ها** — ردیف‌های ثبت‌شده برای ایجاد/ویرایش/حذف مالکان، خودروها و اسناد + خروجی CSV.
8. **تنظیمات برنامه** — پشتیبان‌گیری، بازیابی، شماره‌گذاری، پوسته، دادهٔ نمونه.

اسناد بعد از ذخیره **قفل نمی‌شوند** و هر زمان قابل ویرایش‌اند.

## ۵. تاریخ شمسی

* همهٔ ورودی/خروجی‌های تاریخ در UI به صورت `YYYY/MM/DD` شمسی است (جداکننده‌های `/`، `-` و `.` و ارقام فارسی/عربی هم پذیرفته می‌شود).
* در پایگاه داده مقدار به صورت `DateTime` میلادی ذخیره می‌شود تا مرتب‌سازی و فیلتر بازه‌ای دقیق باشد.
* تبدیل با `System.Globalization.PersianCalendar` انجام می‌شود؛ اعتبارسنجی (سال ۱۲۰۰–۱۶۰۰، ماه ۱–۱۲، روز متناسب با ماه) در `JalaliDate.TryParse` است.
* فیلتر «از تاریخ / تا تاریخ» در صفحات اسناد و گزارش‌ها، ابتدا به میلادی تبدیل و سپس روی پایگاه داده اعمال می‌شود (`EndOfDay` برای تاریخ پایان).

## ۶. چاپ، پیش‌نمایش و PDF

### حالت چاپ پیش‌فرض: درج مقادیر روی تصویر فرم رسمی
برنامه به طور پیش‌فرض از **قالب فرم رسمی ارسالی شما** به عنوان پس‌زمینه استفاده می‌کند
(`CarForm/Resources/PrintTemplate.png` — همان فرم با وضوح بالا، ۲۳۰۴×۳۰۴۰ پیکسل ≈ ۲۸۰ dpi).
در این حالت:

* تمام خطوط، عنوان‌ها، متن اعلامیه و **جایگاه‌های مهر و امضا / کادر پلیس** دقیقاً همان تصویر هستند؛
* برنامه فقط **مقادیر** را در جعبه‌های از پیش اندازه‌گیری‌شده می‌نویسد؛
* خروجی چاپ، پیش‌نمایش و PDF یکسان است.

فیلدهایی که روی فرم چاپ می‌شوند:

| بخش فرم | فیلدها |
|---|---|
| سربرگ | شماره سند، تاریخ سند |
| فروشنده | آدرس، تلفن، شماره دستورالعمل کاردکس، شماره دستورالعمل شماره‌گذاری |
| طرفین | ۱. نام و نام خانوادگی + سمت، ۲. نام و نام خانوادگی + سمت |
| خودرو (۱۶ مورد) | نوع کاربری، سیستم، تیپ، مدل، نوع سوخت، شماره شناسایی (VIN)، تعداد سیلندر، تعداد محور، تعداد چرخ، ظرفیت، رنگ، شماره موتور، شماره شاسی، شماره اتاق، حجم سیلندر، کشور سازنده |
| مالک | نام و نام خانوادگی، نام پدر، شماره شناسنامه/ثبت، تاریخ تولد/ثبت، محل تولد، محل صدور/ثبت، تاریخ صدور، شماره ملی، کدپستی، تلفن ثابت، تلفن همراه، آدرس محل سکونت (مالک حقیقی)، آدرس محل فعالیت (مالک حقوقی) |
| گمرک | شماره پروانه گمرکی، شماره گواهینامه گمرکی، گمرک ترخیص، تاریخ ترخیص |
| بیمه شخص ثالث | شماره بیمه‌نامه، تاریخ صدور، نام شرکت بیمه |
| عوارض شهرداری | شماره فیش، تاریخ فیش، بانک/شعبه |
| مالیات دارایی | شماره فیش، تاریخ فیش، بانک/شعبه |
| بخش خالی فرم | جمع کل فاکتور و توضیحات |

> تصویر/لوگوی مالک فقط در ماژول «مالکان» (کارت پروفایل) مدیریت می‌شود و در ویزارد چاپ نمی‌شود.

### جعبه‌های محل درج مقادیر (`form-layout.json`)
مکان هر مقدار در یک فایل متنی ساده ذخیره می‌شود و **بدون کامپایل مجدد** قابل تنظیم است:

```
%LOCALAPPDATA%\CarForm\form-layout.json
```

هر سطر یک جعبه است (مختصات نرمال‌شده نسبت به تصویر قالب، بین ۰ و ۱):

```json
{
  "Field": "VehicleVin",
  "X": 0.06944, "Y": 0.36316, "W": 0.56944, "H": 0.01974,
  "Align": "Right", "FontScale": 1.0, "Wrap": true
}
```

* `Field` نام منطقی فیلد است (فهرست کامل در `Printing/FormLayout.cs` → `FormFields`).
* `Align`: `Right` / `Center` / `Left`، `FontScale` ضریب اندازه قلم، `Wrap` مجاز بودن شکستن خط.

روش اصلاح چیدمان (بدون کامپایل):

1. در **تنظیمات سند** روی **ویرایش چیدمان** بزنید؛ پنجرهٔ ویرایشگر باز می‌شود و تصویر فرم
   را همراهِ کادر هر مقدار نشان می‌دهد.
2. کادر را با ماوس **بکشید**، از گوشهٔ پایین (راست یا چپ) **تغییر اندازه** دهید و با
   **کلیدهای جهت‌نما** (Shift = ۵ برابر) جابه‌جا کنید. فیلد مورد نظر را از فهرست سمت چپ انتخاب کنید.
3. **ذخیره** را بزنید؛ پیش‌نمایش بعدی بلافاصله از چیدمان جدید استفاده می‌کند.
   برای بازگشت به حالت کارخانه: **بازنشانی**.

> تصویر `form-layout-preview.png` (در ریشهٔ پروژه) تمام جعبه‌ها را روی فرم نشان می‌دهد؛
> شمارهٔ هر کادر با فهرست کنار تصویر مطابقت دارد.
> تصویر `print-preview-simulation.png` یک نمونهٔ چاپ‌شده با مقادیر تست است که چیدمان فعلی را نشان می‌دهد.

### ایمنی در برابر متن‌های بلند
* هر مقدار درون جعبهٔ خود با `TextWrapping` + `TextTrimming` نمایش داده می‌شود.
* اگر متن از عرض جعبه بیشتر شود، اندازهٔ قلم آن به طور خودکار کوچک می‌شود (`AutoShrinkText`).
* تعداد ردیف‌های فاکتور محدود است (`MaxInvoiceRows`) و مازاد در ردیف «سایر موارد» جمع می‌شود.
* هیچ مقداری بیرون از کادر خود نمی‌رود، بنابراین ساختار فرم هرگز به هم نمی‌خورد.

### حالت برداری (بدون تصویر قالب)
اگر در تنظیمات سند گزینهٔ «چاپ مقادیر روی تصویر قالب فرم» را خاموش کنید،
برنامه یک فرم برداری RTL با همین ترتیب بخش‌ها می‌سازد (مفید برای چاپ روی کاغذ بدون نیاز به تصویر
یا زمانی که می‌خواهید فرم را با فونت/رنگ دلخواه بازطراحی کنید).

### معماری
```
SalesDocument + Company + PrintSettings + form-layout.json
        │
        ▼
TemplateFormRenderer ──► FixedDocument / FixedPage (A4)
        │                     (تصویر قالب + مقادیر در جعبه‌ها)
        ├──► DocumentViewer      (پیش‌نمایش)
        ├──► PrintDialog         (چاپ روی پرینتر)
        └──► FixedDocumentExporter ──► MiniPdfWriter ──► *.pdf

DocumentFormRenderer  ──►  همان خروجی‌ها در حالت برداری (بدون تصویر)
```

* استفاده از `FixedDocument/FixedPage` باعث می‌شود مقیاس‌گذاری (DPI پرینتر یا PDF) جای فیلدها را تغییر ندهد.
* خروجی PDF از **رندر همان FixedPage** ساخته می‌شود (رزولوشن پیش‌فرض ۳۰۰dpi)، پس PDF دقیقاً همان چیزی است که در پیش‌نمایش می‌بینید.
* خروجی PDF تصویری است (متن آن قابل جستجو نیست) تا فیدلیتی فارسی ۱۰۰٪ حفظ شود.

## ۷. پایگاه داده و Migration

در این نسخه از `EnsureCreated` (به همان روش Seed) استفاده شده تا برای کاربر تک‌کاربره ساده و بی‌دردسر باشد.
اگر بعداً Migration لازم شد:

```bash
dotnet tool install --global dotnet-ef
dotnet ef migrations add Initial --project CarForm/CarForm.csproj
dotnet ef database update --project CarForm/CarForm.csproj
```
سپس در `DatabaseInitializer.Initialize()` فراخوانی `EnsureCreated()` را با
`db.Database.Migrate()` جایگزین کنید.

### پشتیبان‌گیری و بازیابی
* **پشتیبان**: دکمهٔ «تهیه نسخه پشتیبان» یک کپی با نام `carform-backup-YYYYMMDD-HHMMSS.db` می‌سازد
  (با `VACUUM INTO` که حتی هنگام کار برنامه هم فایلی سالم و یکپارچه تولید می‌کند؛ در صورت عدم پشتیبانی، کپی ساده انجام می‌شود).
* **بازیابی**: فایل پشتیبان انتخاب می‌شود، ابتدا از پایگاه دادهٔ فعلی یک نسخهٔ امنیتی
  (`carform-before-restore-…db`) گرفته شده، سپس جایگزین می‌شود و برنامه اعلام می‌کند که باید بسته و دوباره اجرا شود.

## ۸. افزودن امکانات جدید

* **ردیف پیش‌فرض جدید در فاکتور** — در `AppSettings.CreateDefaultInvoiceItems()` (یا از طریق رابط کاربر) اضافه کنید.
* **فیلد جدید در فرم چاپی** —
  1. پراپرتی را به `SalesDocument` اضافه کنید،
  2. آن را در `DocumentFormRenderer` (بخش مربوط) به `FormCell` اضافه کنید،
  3. در صورت نیاز فیلد ورودی را در مرحلهٔ مربوطِ `NewDocumentWizardView.xaml` قرار دهید.
  (Migration خودکار نیست؛ برای دیتابیس موجود باید ستون اضافه شود یا از Migration استفاده کنید.)
* **صفحهٔ جدید** — یک `IPageViewModel` بسازید، View متناظر را در `MainWindow.xaml` به صورت `DataTemplate` ثبت کنید و در `ServiceCollectionExtensions` رجیستر کنید.

## ۹. نکات طراحی

* تمام عملیات پایگاه داده از طریق `IDbContextFactory<AppDbContext>` انجام می‌شود (هر عملیات یک DbContext کوتاه‌عمر) تا هیچ قفل یا نشتی اتصالی باقی نماند — برای بازیابی پایگاه داده ضروری است.
* `SalesDocument` یک **Snapshot کامل** از اطلاعات خودرو و مالک است؛ انتخاب خودرو/مالک در Wizard فقط مقادیر را «کپی» می‌کند و بعد از آن همه چیز دستی ویرایش می‌شود (بهترین روش برای اسناد چاپی که نباید با تغییر موجودیت تغییر کنند).
* اعتبارسنجی با `INotifyDataErrorInfo` است و پیام‌های خطا کنار هر فیلد (به صورت `{Binding [Name]}`) نمایش داده می‌شوند.
* لاگ تغییرات (Audit) در لحظهٔ ذخیره و در همان تراکنشِ کاری ثبت می‌شود و هیچ‌گاه مانع عملیات اصلی نمی‌شود.
